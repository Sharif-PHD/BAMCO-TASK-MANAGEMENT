# ممیزی کد و نسخه یکپارچه BAMCO

## دامنه بررسی

- شاخه مبنا: `main`
- برنامه: Static HTML/CSS/JavaScript با اتصال مستقیم به Supabase
- دیتابیس بررسی‌شده: پروژه Production با شناسه `zhhongjhhbvpmoquvkhl`
- تغییر دیتابیس: هیچ‌کدام

## علت اصلی ناپایداری ظاهری

کد اجرایی از چند لایه تاریخی تشکیل شده بود. `index.html` نه فایل CSS را به‌ترتیب بارگذاری می‌کرد، دو بلوک CSS داخلی داشت و چند ماژول JavaScript نیز پس از `DOMContentLoaded` فایل CSS یا Style جدید اضافه می‌کردند. به همین دلیل نتیجه هر تغییر به ترتیب بارگذاری و تعداد `!important`ها وابسته بود.

چهار فایل JavaScript دیگر نیز از داخل `ui-extra-20260906.js` به‌صورت پویا بارگذاری می‌شدند. این رفتار تشخیص نسخه فعال و رفع تعارض را دشوار می‌کرد.

## راهکار نسخه Clean Release

1. تمام CSSهای ثابت و Styleهای داخلی HTML با حفظ ترتیب Cascade در `bamco-unified.css` ادغام شدند.
2. Design Tokenهای واحد برای رنگ، Border، Radius، Shadow، Typography و حالت Focus تعریف شد.
3. فرم‌ها، دکمه‌ها، جدول‌ها، پنل‌ها، Dialogها، هشدارها و پیام‌ها از یک زبان بصری مشترک استفاده می‌کنند.
4. ناوبری عمودی به نوار افقی واکنش‌گرا تبدیل شد تا فضای کاری جدول‌ها آزاد شود.
5. میزکار جدول به کانبان و آرشیو اضافه شد: مرتب‌سازی ستونی، نمایش/پنهان‌کردن ستون، تراکم سطر، تمام‌صفحه و بازنشانی تنظیمات.
6. تب جدید «تقویم و گانت» در Build نهایی به‌صورت صریح بسته‌بندی و با Design System هماهنگ شد.
7. ماژول‌های پویا به Scriptهای صریح و قابل ممیزی تبدیل شدند؛ Loader قدیمی در Release دوباره آن‌ها را بارگذاری نمی‌کند.
8. کدهای رفتاری اصلی بدون بازنویسی منطق کسب‌وکار نگه داشته شدند تا قابلیت‌های موجود حذف نشوند.
9. نسخه نهایی در پوشه `release/` ساخته می‌شود و شاخه اصلی تا زمان تست پذیرش Production جایگزین نمی‌شود.

- کانبان، آرشیو، افزودن، ویرایش، حذف و بازگردانی

- داشبورد و فیلترها
- مدیریت افراد و نقش‌ها
- پیام داخلی و سوابق پیام
- قالب پیام و استیکر
- Import/Export اکسل
- تنظیمات حساب و تصویر پروفایل
- تحویل دائم و موقت خودرو
- Bridge سازگاری Storage/Outlook
- تقویم شمسی و نمای گانت

## تطبیق فایل‌های اکسل و دیتابیس

- کانبان: ۱۱۱ رکورد در Excel و ۱۱۱ رکورد فعال در Supabase؛ `legacy_id`های ۱۲۱۹ تا ۱۳۲۹ کامل و یکتا هستند.
- آرشیو: ۱۲۱۸ رکورد در Excel و ۱۲۱۸ رکورد آرشیوشده در Supabase؛ `legacy_id`های ۱ تا ۱۲۱۸ کامل و یکتا هستند.
- بنابراین کمبود تعدادی وجود ندارد؛ با این حال توزیع مسئول‌ها در آرشیو با فایل مرجع یکسان نیست و برای اصلاح داده به تأیید جداگانه نیاز است.
- در فایل مرجع آرشیو، برخی فرمول‌های ستون L دارای خطای `#REF!` هستند؛ مقدار نمایشی ذخیره‌شده وجود دارد، ولی خود فرمول معیوب است.

## اصلاح Import/Export اکسل

- تاریخ‌های شمسی هنگام Import به ISO تبدیل می‌شوند.
- تاریخ‌ها در Export به‌صورت Date واقعی Excel با قالب `yyyy-mm-dd` نوشته می‌شوند، نه متن تزئینی.
- شناسه، روز یادآوری، روز تأخیر و مهلت اقدام به‌صورت عددی صادر می‌شوند.
- Import آرشیو رکورد را با `archived=true` و زمان آرشیو وارد می‌کند؛ Import کانبان رکورد فعال می‌سازد.
- تبدیل تاریخ و نوع سلول‌ها با تست خودکار `tests/data-io.test.mjs` پوشش داده شده است.

## نکات دیتابیس

جداول اصلی Production دارای RLS هستند. در این تغییر هیچ Migration اجرا نشد. Advisoryهای موجود باید در یک کار مستقل بررسی شوند؛ تغییر Policy یا Index هم‌زمان با Refactor رابط، دامنه ریسک را بی‌جهت افزایش می‌دهد.

## ساخت نسخه نهایی
